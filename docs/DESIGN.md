# myvisa — Design rationale

## v2 (Phase 2): cinematic and motion-led

After the Phase 1 review, the client asked for a design that is *very* different and has a lot of animation. The tokens below are unchanged, but the composition is now cinematic:

- **Dark, full-viewport openers.** Every page starts on ink-950 with drifting teal and gold light leaks. The header re-themes itself over any section marked `data-surface="dark"`.
- **Oversized type with word-by-word mask reveals** (`SplitReveal`). Splitting is per word, never per letter, because letter splitting breaks Arabic joins. Gradient words get `wordClassName`, since `bg-clip-text` can't paint through transformed children.
- **Interactive dotted globe** (`components/globe`) on a 2D canvas: 4,208 real land dots (Natural Earth, generated by `scripts/build-globe-dots.mjs`), routes from Riyadh with travelling pulses, drag with inertia, and a sway that keeps Riyadh in view. It turns toward the destination picked in the hero search. Lazy-loaded, it pauses off-screen, and it renders a static frame for reduced motion.
- **Scroll-driven sections:**
  - a pinned horizontal destinations gallery that moves in the reading direction
  - a sticky "how it works" device that plays one scene per step, with a progress rail
  - an ink-in paragraph on About
  - a footer wordmark that rises letter by letter (Latin letters only)
- **Tactile UI:**
  - 3D tilt cards with glare
  - cursor spotlight on bento cards
  - magnetic CTAs
  - CSS marquees that follow the reading direction
  - layout-animated filters and pills
  - a circular-reveal mobile menu
  - an ink-curtain transition between routes (client navigations only, so first paint and LCP aren't delayed)
- **Smooth scrolling** with Lenis, switched off for reduced motion. Dialogs and scroll areas opt out with `data-lenis-prevent`.

Everything that moves respects `prefers-reduced-motion`.

## v1 foundations (Phase 1)

**Direction: "editorial luxury travel".** The reference point is a private concierge, not a travel-agency flyer: generous whitespace, one confident typeface per role, colour used sparingly, and depth from soft layered shadows rather than borders and gradients. The page should feel calm, and the price should feel honest.

Live reference: `/style-guide` (Arabic) and `/en/style-guide`.

## Colour

Brand palette (Oct 2026) taken from the client's logo "تأشيرتي My VISA": turquoise `#34C1C3` and royal blue `#2B4FA1`. The scale names predate the logo and were kept so no component changed: `gold-*` is now the brand turquoise, `teal-*` the brand blue, `ink-*` a blue-navy, `sand-*` a cool paper.

| Role | Token | Light | Dark | Notes |
|---|---|---|---|---|
| Text / ink | `foreground` | ink-900 `#0B1830` | sand-100 `#F3F7F9` | 16.4:1 on paper |
| Page | `background` | sand-100 `#F3F7F9` | ink-950 `#071023` | cool paper |
| Cards | `surface` | `#FFFFFF` | `#0E1C33` | |
| Decision / CTA | `primary` | gold-400 `#34C1C3` (turquoise) | gold-400 | **navy text on turquoise (8.0:1)** |
| Turquoise as text | `accent-text` | gold-700 `#11686B` | gold-300 `#6BD3D6` | 6.1:1 / 9.7:1 |
| Trust / progress | `secondary` | teal-500 `#2B4FA1` (brand blue) | teal-300 `#7C9BDB` | completed steps, links, focus |
| Muted text | `muted-foreground` | ink-500 `#4C5E7A` | ink-300 `#97A6BE` | 6.1:1 / 7.7:1 |
| Semantic | `success · warning · danger · info` | AA on paper | AA on ink | each has a `-soft` tint |

**The one hard rule:** brand turquoise `#34C1C3` on paper is only **2.04:1**, so it fails WCAG for text. Turquoise is therefore a *fill* (buttons, highlights, price bar) with navy text on it, and whenever it must be text we use the deep shade. It is reserved for the single most important action on a screen.

Dark mode swaps semantic tokens only, so components never branch on theme. The same trick makes any section "inverse": add `className="dark"` to a container (see the hero map panel).

## Typography

| | Arabic (default) | English |
|---|---|---|
| Display | **Alexandria** (variable) | **Instrument Serif** (editorial, high-contrast) |
| Text / UI | **IBM Plex Sans Arabic** 400/500/600 | **Inter** (variable) |

- Fluid scale with `clamp()` from 360 → 1440 px: `display-2xl` 44→84 px down to `caption` 13 px.
- Line-height and tracking switch by script through CSS variables: Arabic display 1.3, body 1.85, **zero letter-spacing ever** (a global `*:lang(ar)` rule enforces it, because tracking breaks Arabic joins). Latin display 1.04, −0.02em.
- Latin digits (0–9) for prices, dates and order numbers (`ar-SA-u-nu-latn`), which is what Saudi users read on banking and government apps. Codes, phones and OTPs always render LTR.
- Only the Arabic fonts are preloaded (default locale); Latin fonts load on demand. Everything is self-hosted by `next/font` (no Google requests at runtime).

## Space, shape, depth

4 px grid · radii 8/12/16/20/28 · pill-shaped buttons · cards at 20–28 px. Shadows are 2–3 stacked layers tinted with ink (`--shadow-rgb`), switching to pure black in dark mode. A 3.5% paper-grain overlay gives surfaces an editorial, printed feel.

## Motion

`motion` (Framer Motion). Entry is a fade-and-rise on `ease-out-expo` (700 ms), staggered by 80 ms. Micro-interactions run 150–250 ms. Signature moments are the stamp "thunk" (spring), animated route arcs, number counters, and a magnetic primary CTA (mouse only). `MotionConfig reducedMotion="user"` and a global CSS guard disable all of it for users who ask.

## Signature elements

1. **Route arcs:** an SVG map of arcs leaving Riyadh (about 3 KB, no WebGL) with flowing dashes and planes along the paths. The map is never mirrored in RTL. On phones it is centre-cropped so it stays legible.
2. **Passport stamps:** pure SVG (circle, oval, rect × teal, gold, ink, danger), with worn-ink texture from `feTurbulence`. Used on destination cards (on hover), in hero art, and in empty states.
3. **Destination card:** full-bleed photo, flag chip, processing time, and a "from" price. On hover the card lifts, the photo zooms slowly, and a stamp appears.
4. **Price breakdown:** our competitive edge made visible. Embassy fee and service fee sit on separate lines, VAT is labelled "on the service fee only", a proportion bar shows the split, and our share is stated outright.
5. **Boarding pass:** order tracking styled as a boarding pass. Route header, tear line with punched notches, and six milestones (vertical on phones, horizontal on desktop), with a pulsing current step and a deterministic barcode.

## RTL

Logical properties everywhere (`ms/me/ps/pe/start/end`). Directional icons use the `flip-rtl` utility. Radix receives the direction through `Direction.Provider`. Phone, OTP and code fields are forced LTR. Verified at 390 px with zero horizontal overflow; Radix's hidden radio inputs, which overflow in RTL, are neutralised in `globals.css`.

## Placeholders to replace

- Brand mark: the client's logo is in `apps/web/src/assets/brand/` (light, dark-surface and icon-only PNGs, cut from a 628 px JPG). Swap in vector (SVG) artwork when the designer provides it.
- CR number, VAT number, WhatsApp number: placeholder values until they move into admin Settings (Phase 3).
- Payment marks are text chips. Use the official mada / Apple Pay / STC Pay artwork from the chosen gateway's brand kit.
- Destination photos come from Unsplash for now.
